Panel system, the generic vocabulary

A small fixed set of classes for the design sidebar. This is being built for Text Properties first, then applied unchanged to Sticker, Shape, Fill, Canvas, the tool panels, the state panels and Auto Glitter. Every color, font and radius is from _tokens.scss. The panel adds only the tokens and classes below, scoped to .design-panel, to replace the current setting-label / effect-option-* / functional-control-group-* vocabulary.

Read this before implementing

All docs live in docs/panel-redesign/. The full build spec is PANEL-REDESIGN-SPEC.md there: tokens, the class list, the non-obvious rules, the icons to reuse vs add, conditional elements, the component ledger, what stays as-is, what is mockup-only, and the migration contract. PANEL-REDESIGN-ARTBOARD-DIFF.md maps each artboard to its live app section. This sheet is the visual summary.

The artboards are a spec, not paste-able CSS. Each .dc.html file has its own inline <style> written to render that one isolated frame. Build the real _properties.scss from the RULES, not by copying an artboard's stylesheet.

Mockup shortcuts that must NOT survive into production:

  • Non-row body items reserve the revert gutter with margin-right here. In production that is a container padding-right: the body owns the gutter, children still carry no margin. The rule "separation is the parent's gap, never a child margin" still holds.
  • .disc uses negative margins to bleed its divider full width. In production the divider is a border on the body edge or a full-bleed pseudo-element, not a negative margin.
  • Per-artboard --pad, --r-card etc. are re-declared in every file. In production they are declared once on .design-panel.
  • Inline style= on individual elements (montage colours, one-off widths) is mockup data, not a pattern. Real values live in classes and tokens.

Do not wipe the current styling. Strategy (from docs/panel-redesign/PLAN-property-panel-system.md §6): add the new .property-* classes alongside the old ones, migrate the renderer and the known JS-to-DOM couplings one work package at a time, delete the old property-only vocabulary at the end. Shared primitives stay and are reused: the switch / pill toggle (switch-track mixin, also used in Settings), the focus ring, inset-surface, the icon set, the token scales. tests/panel-parity.js guards that no element id is lost.

What to hand the implementer

  • This canvas (the visual target) + this System Key (the rules to build from).
  • docs/panel-redesign/PLAN-property-panel-system.md and its work-package list (WP1..WP10). Build in that order: collapsibility opt-in, then the token / row / typography SCSS, then the renderer naming rule, then revert, then conditionality, then module rows, then the text panel off its legacy template, then the canvas-size vocabulary, then gallery / filters, then the theme + mobile sweep.
  • The Deltas sheet: what is net-new (build it), what is being replaced (migrate it), what is kept (leave it), what is parked (do not build it).
  • The preservation contract: node tests/panel-parity.js and node tools/panel-audit.js green before and after every work package; no manager file (TextGlitterManager, ShapeGlitterManager, ...) edited to accommodate layout.
  • One instruction that prevents the last failure: a rule that needs :has() to read structure or :not() to carve exceptions means the markup is wrong. Fix the class, not the selector.

Spacing, the only values that exist

Every boxed container gets --pad on all four sides. Every stack separates children with one gap. No child carries a margin.

--pad 8pxuniform inset: card, module header, module body, disclosure header
--row-gap 4pxrow to row inside a body
--block-gap 8pxcard to card
--group-gap 14pxL1 group to L1 group

No .set / sub-label level. Align (Horizontal + Vertical rows) and Flip are ordinary rows with an icon control, matching the Font Alignment card exactly, so their label is the same 12px as Position, Size and Scale.

How the SCSS is written important

No long list of hyper-specific selectors. The last attempt failed because it specced behaviour and then implemented it as :has() chains and :where(:not():not()) exclusion lists. That is what is being replaced, not extended.

  • A repeating concept gets its own class (.row, .panel-card, .numf, .asset). Variants are modifier classes on the same element (.row.is-pair), never a descendant selector reaching into it.
  • A more specific class is added alongside the generic one when JS needs a hook: class="row is-pair transform-position". The specific class carries no layout, only the binding.
  • CSS custom properties for every value that repeats or that a theme overrides. All geometry is tokens on .design-panel; a card that needs a tighter gutter re-sets the token, it does not add a selector.
  • Mixins for a genuinely shared multi-property pattern (switch track, focus ring, inset surface). Not for one-offs.
  • Nesting one level deep, for state and variants only (&:hover, &.is-open). Nesting that MIRRORS THE DOM (.panel .group .card .row .label) is the bad practice: it welds structure into selectors, so moving an element breaks its styles, and specificity climbs. SCSS nesting purely to group related rules visually is fine as long as it compiles to flat, single-class selectors.
  • Organisation: one file, _properties.scss, ordered sections with a header comment each (tokens, typography, row types, grouping, modules, responsive).
  • If a rule needs :has() to sniff structure or :not() to carve out exceptions, the markup is wrong. Fix the class or the structure, not the selector.

One segmented control, and when NOT to use it consistency

There is ONE segmented control: one line, never wraps. The old wrapping variant is gone. Choose by what the options are, not how many happen to fit today:

.seg2 to 3 fixed short options that will not grow: Mode, Style, Edges, Layering, H / V align (icons).
.sel dropdownanything enumerated, could grow, 4+, or "set once": Source (same control in every panel, Canvas has 4 modes), Case, Placement, Blend, Palette.
.choice-grida genuine gallery of many equal choices: font tag filters, shape picker. Separate bordered buttons that wrap. Never a wrapped .seg.

Source is a dropdown everywhere, even where 3 modes would fit as a segmented, so it reads and behaves identically across Text, Sticker, Shape, Fill and Canvas.

Sliders only where a value is bounded

A slider needs a real 0 to max range: opacity, font size, border width, letter / line spacing, rotation (0 to 360). X, Y, W, H, Scale have no natural maximum, so they are number fields only (the Figma pattern). This also removes the tiny-slider problem in pair rows. No scrub fields.

Value and revert

In a row the value sits in an editable field and the 16px revert slot is always reserved, so a value crossing its default never reflows the grid. The revert icon paints only when the value is off-default, and is never hover-only. A pure readout (there are almost none now) stays plain tertiary text.

In a module header the revert is present-only, not reserved, because nothing sits below it to stay aligned with. The chevron is the right-edge anchor; the revert appears just left of it when the module is off-default. That is why the collapsed Shadow header has no gap before its chevron and the Fill header does.

The revert column is reserved on every row - value, slider, segmented, dropdown, toggle alike - so one right edge runs down all the rows. Alignment, Source and Mode have no default to return to, so their slot just stays blank. Non-row block elements - asset cards, notes, full-width buttons, group footers - do NOT reserve it; they span the full content width (16px inset each side). Two side-by-side action buttons (Open project / Save project) stay a 2-up.

Solid color is an editable field

A Solid source shows .colorfield: the swatch plus the hex, in a field you can select and paste a code into, not a read-only chip. Same height and radius as every other field.

The Content / asset section is a module

Wherever a panel has an asset (Sticker, Shape, Brush tip), Content is a .panel-module: a header in the chrome bar (name, revert, chevron), then the .asset row and any settings in the body. Same shell as the Transform and effect modules. Shape used to be a plain card with a bare asset row; it matches the rest now.

Shared asset anatomy. .asset, a Layers-panel row and an Auto Glitter match row are the same object: 34px thumbnail, name 12 / 600, meta 11 / tertiary, 8px gap. What differs is set by context, not taste: the module .asset keeps the sunk inset (it is one field's current value, acted on by a text button); list rows are carded on the panel ground and act through icon buttons.

Concentric corner radii app-wide

Rounded elements nested inside other rounded elements do NOT repeat the same radius. Each inner radius is its parent's radius minus the gap between them, so the curves stay parallel; recursively, so a deeper nest is tighter still. Moving outward, add the gap; moving inward, subtract it. Floor at 3px.

The panel scale: window 8, card / module 6, field and button 4, asset surface and swatch 3. Tokens --r-panel / --r-card / --r-field / --r-inner. Applies to every panel and should be the rule across the whole app, not just here.

Label text size

Property labels are 12px today. Recommendation: drop to 11px to match the value fields, the way Figma and Photoshop size panel labels. One token change (--property-label-size). Keep the group label at 10.5px and the block title at 12px. Not yet applied to the artboards, which stay at 12px so they read as one set.

Booleans: one primitive

Every boolean is a toggle switch (.row.is-toggle): label on the left, switch right-aligned to the value column (same right edge as every value field), then the reserved revert slot. Lock aspect ratio, Relative, Resample, Scale Textures / Effects, Pressure, Clean edges, the Selection options, Tune matched glitter hue. Nothing is a left-aligned checkbox. The one switch that sits elsewhere is the module / effect enable, which leads its header.

Actions: contextual vs form submit

A contextual action acts on the block right above it: Fit box to text, Reset Effects (which sits below a full-bleed hairline, full content width, its own even padding). A form submit commits a set of fields and gets a footer: a full-bleed divider, its own even padding, visually detached from the inputs. Same treatment as the filter drawer's Clear all / Show results bar. Applies to Project's Open / Save, Image Size's Scale design, Canvas Size's Resize canvas, the no-selection Apply. All full-width buttons span the full content width now - no revert-column clearance.

Buttons still stack one per line, full width. A two-up row is allowed only for exactly two actions whose labels both fit (Open / Save). Group / Duplicate / Merge down / Delete stack.

Empty and populated states are both drawn, both labelled

Any component with a filled form and an empty form is shown twice on the sheet, each with a small Shown when empty / Shown when populated tag, so the implementer never has to guess which markup is which. Color selections is the example.

Label tooltips

Not every label. A label MAY carry a schema title: for a terse or technical term (Merge, Detail, Feather, Contiguous, Dot gap). It renders cursor: help and reveals on hover; obvious labels (Opacity, Rotation, Size) stay bare. This is already how the schema works, the design just styles .property-label[title].

Why Color Fill Settings has a "Color Picker" tag

It is a tool panel, not a layer panel. It only appears when the Color Picker tool is active on a glitter fill (syncToolSettingsSectionVisibility), and it configures how that tool selects colors on the fill's mask. The tag names the tool it belongs to, same as the Brush tag on Mask Settings, so the user knows these settings are the tool's and will change when they switch tools. Photoshop options-bar model.

Standalone text blocks

A lead line or note that stands on its own (no-selection intro, multi-select summary) gets its top spacing from its own padding-top and its bottom spacing from the parent's gap so the two are equal, and never has a divider immediately after it. The "more space below than above" was a body top-pad plus a group divider stacking under a zero-pad line.

Disclosure label

The Advanced disclosure is labelled with a topic, at most two words, never a list of its contents. "Advanced" is the default; a pure-purpose one may be topical ("Adjust color", "Cleanup"). Not "Adjust color, hue, saturation, brightness".

Collapsed module summary

The summary is ONE identifier, never a value dump. Fill shows the glitter name ("Holo Foil"), Border and Shadow show the source ("Glitter" / "Solid"), Transform shows nothing (the revert icon is the "edited" signal). The swatch carries the color. Offsets, widths and percentages live inside the expanded module, not in the summary line.

Units

Shown only where a value could be misread without it. px is never shown on Position or Size (it is the only unit they ever use, and Figma / Photoshop omit it). Degrees and percent are always shown, because rotation could be read as radians and Scale vs Opacity are both 0 to 100.

Responsive: container queries, never media queries

The mobile drawer moves these exact sections, so the same DOM renders at ~450px (resizable desktop panel) and ~330px (drawer). .settings-subsection gets container-type: inline-size. Below ~360px: X/Y and W/H pairs stack one field per line, the label column shrinks. See the Narrow artboard.

Asset browser

Same chrome as the panels. A slim header (Back + title + count), a search row (input + Filter button), an optional armed picker strip that names the destination, an active-filter chip summary, then the content: a category grid (2-up folder cards) by default, an asset grid (4-up swatch / tile cards) inside a category or in search results.

The filter drawer is redesigned per PLAN §3.8: each group is a .property-group-label (the same single uppercase level, not a fourth filter-label) over a chip row, separated by hairline dividers, not cards. The nested max-height:200px; overflow:auto scroll trap is removed; the panel scrolls. Colours are round swatch chips, everything else a pill. Clear all / Show results pinned at the bottom.

Three layouts, chosen by the collection, and that is fine.

  • Glitter, stickers (100s to 1000s): a category folder grid, with a By category / Show all toggle. "Show all" is every item visible, grouped under category headers, nothing hidden, nothing collapsed. Not a flat mixed grid.
  • Brush tips: basic brushes listed flat as today, then Brush sets as folders (like glitter). Opening a set is its own screen: a back line, the set name, a Source & Usage credit block (attribution + link), then its tips. Search / filter scope to the current screen; the back line clears the scope.
  • Shapes (~48): too small for folders and too small to hide. Every category shown, grouped under headers, always. Same layout as glitter's "Show all".

No Featured row. Grid columns are a container query (3-up narrow, 4-up default, 5-up wide), same mechanism as the panels. An animated item gets a corner play glyph.

Item chrome: an animated item (glitter or sticker) carries a small play-glyph badge in a corner (it affects the exported GIF, so it earns the mark). Brush sets get a set title and a Source & Usage credit block (attribution + link) above their tips; individual basic brushes do not. The active-filter Clear all is a bordered pill with an x icon, not a plain word.

Asset meta line (dimensions and animation): W × H, then for animated assets · N frames · R fps. Fallbacks the code already carries: variable rate renders · variable, no rate renders just · N frames, no dimensions omits that segment. The renderer drops empty segments, it never prints "0 fps" or "undefined".

Scroll region + sticky footer

Auto Glitter is the one panel whose body must scroll under a pinned action bar. The panel is a flex column with a fixed height: a pinned preview (flex: 0 0 auto), a scroll region (flex: 1; overflow: auto) holding the groups, and a footer (flex: 0 0 auto, hairline on top) with Cancel / Create N layers. No group inside the scroll region changes; the same .card, .row, .glabel, revert gutter and .is-check apply. Color Matches is a list of region → matched glitter rows, each a swatch pair, a name, a match %, and a Change chip.

Layers panel parity

Left side, but it should read as one family with the rest. Same Y2K bar (icon, "Layers", count, a New Layer action, a collapse chevron). A layer row is one card: drag dots, a 34px swatch, name + type meta (plus a Masked / Locked badge), then visibility and lock icon buttons. States: .active (accent border + tint), .selected, .is-hidden (dimmed swatch and name), .is-locked (no drag handle). The bottom bar of add / clone / go-to / delete icon buttons sits in the panel chrome, same tokens as the property panels.

Collection credit block

From .asset-collection-credit, reformatted, same information: a Source & usage label, a byline (Created by <a>), a meta row of dot-separated muted spans (license, archivist), an optional <details> archival note (collapsible, drawn open on the sheet), and a links row (View archived set). It lives at the top of a brush set's page, inside a card, above the tips grid. Basic brushes have no credit.

Rules that keep it from drifting

  • Spacing is the parent's gap or nothing. Never a margin on a child.
  • Cardness is the .panel-card class. A block inside a block is not a card.
  • One uppercase level, the group label. One body label size, 12px.
  • Conditional content: hidden on the outermost owned node, then .row[hidden]{display:none} and .panel-card:empty{display:none}.
  • No :has() chains, no :where(:not():not()), no feature-named selectors.
  • No card in a card. No fourth label level. No per-element margin math. No wrapping segmented.

Applying to the other panels

The Panels Inventory artboard lists all twelve right-panel types. Sticker, Shape, Fill, Canvas, the two tool panels and the three state panels are drafted on their own pages, and the asset browser (gallery, category, search + filter, shapes, brush tips) on another. Sticker and Shape share Text's structure. Fill is the minimal case (one module + a read-only Mask summary) and proves the system does not sprawl. Canvas Properties is the density stress test: its Size group is the real two-mode control (Image Size, which scales content and keeps Scale Textures / Scale Effects, vs Canvas Size, which crops or extends and carries the anchor and an extension fill), re-authored from the modal settings-row-* markup. Auto Glitter is the layout stress test: a scrolling body with a pinned "Create Layers" footer, a live status host and a dynamic list, needing .panel-scroll + .panel-footer. Design one at a time, then re-check earlier ones.
