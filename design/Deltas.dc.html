Deltas: current app vs this design

Every line below is the codebase as it stands today compared to what this design specifies. It is written to hand to an implementer.

Add = this design shows it as a real control; the app has no equivalent yet.

Remove / replace = exists in the app now; this design eliminates or supersedes it.

Keep = exists in the app now; this design preserves it, possibly restyled.

Parked = discussed, not in this design. Revisit separately.

Nothing here may break the preservation contract: tests/panel-parity.js requires the set of element ids in each section to stay identical.

This sheet plus the Panels Inventory are the running record; they stay current as the panels iterate.

System rule, not a feature: concentric radii

Rounded elements nested in rounded elements step the radius down by the gap between them (window 8, card 6, field 4, inner 3), recursively, floored at 3. Tokens --r-panel / --r-card / --r-field / --r-inner. Apply across the whole app.

Add — not in the app today

Appears in the mockup as a real control. Confirmed in scope.

Editable Scale field

Today Scale is scaleReadout: true, display only. Make it a field that types a percent and drives W / H proportionally.

Shape corner radius

LayerType.SHAPE has no radius control. Add a bounded slider on the shape asset (rounded-rectangle and similar).

Type-to-set number fields

Most numeric values are slider-only today. Every value in the mockup is an editable field; X / Y / W / H / Scale have no slider at all.

Container-query responsive layout

.settings-group-two-column is 2-up at every width, no query anywhere. Needs container-type: inline-size plus stack rules under ~360px.

Opt-in collapsibility

initializeAdvancedDisclosures() stamps every .subsection-content-group as collapsible. Make it opt-in per schema item, so only modules and the Advanced disclosure collapse.

Panel scroll region + sticky footer

Auto Glitter needs a scrolling body with a pinned "Create Layers" action, a live status host and a dynamic results list. Needs .panel-scroll + .panel-footer primitives that do not break the spacing rules.

Multi-thumbnail category schema

Category grid tiles show a 4-swatch montage (glitter/stickers) or 3-example montage (brush sets); the real schema (data/*-categories.json, every category) only has one icon string, rendered singular by createCategoryCard() in AssetBrowser.js. Needs a decision: curated thumbnails[] array vs. auto-picked from category members at render/save time. Whichever is chosen, selection must be stable across renders — never re-randomized — or the tile stops reading as a consistent identity for that category. See BrowserGallery.dc.html / BrowserShapesBrush.dc.html spec notes.

Category-specific empty-state copy

AssetBrowser.loadCategoryItems() shows one generic "No items in this category" message for every empty category today. The "User Uploads" empty state (upload prompt + action button) in BrowserEmpty.dc.html needs either a category.id === 'user-uploads' special case or a general per-category empty-copy schema field.

User Uploads must always appear in the category grid, even at 0

populateCategoryCards() (AssetBrowser.js) does if (count === 0) return; — every zero-item category is skipped, so user-uploads currently vanishes from the grid until the user's first upload. Needs an always-show exception, ideally a schema flag (e.g. alwaysShow: true) rather than hardcoding the id in AssetBrowser.js.

User Uploads sorts last, not by JSON order

this.categories is just await response.json() array order, no sort step. user-uploads is currently the first entry in data/sticker-categories.json, so it shows first. Needs to move to the end of the grid regardless of file order — either reorder the JSON or add explicit sort-last handling.

User Uploads tile thumbnail should show the user's own upload

createCategoryCard() only reads the static category.icon string today. For user-uploads specifically, once the user has any uploads the tile should show one of their own images (most recent, for a consistent "as it changes" identity) instead of a generic icon; falls back to the generic upload glyph at 0.

Header icon gap closed on the two leaf-detail boards

BrowserCategory.dc.html and BrowserBrushSet.dc.html were missed in the first collapsed-icon pass and had no search/filter icons at all — real inconsistency, not a style nit. Added to both; BrowserCategory.dc.html's filter icon carries a dot since its .summary already shows 2 active filters.

.catdesc was a bare <p> with no margin reset

The browser's default paragraph margin was stacking on top of the intentional 8px flex gap in .catmeta, making the spacing around the description read as irregular even after the earlier symmetric-8px pass fixed the surrounding blocks. .credit's own internal paragraph already had margin:0 (the correct precedent) — .catdesc just never got it. One-line fix.

Search/filter collapse to header icons on EVERY board, desktop included

Ryan-said: this was mobile-only-collapsed / desktop-always-expanded; now it's one pattern everywhere. Default state on every board (BrowserGallery.dc.html, BrowserGalleryStickers.dc.html, BrowserShapesBrush.dc.html ×2, BrowserShowAll.dc.html, BrowserEmpty.dc.html panels 1&2): two icon buttons in the header next to the title, no reserved full-width row. Also: Ryan-said even an active search/filter must be manually collapsible — the old rule ("stays expanded while active") trapped the user. Added .closebtn to every expanded/active row (BrowserFilter.dc.html, BrowserEmpty.dc.html panel 3, BrowserMobile.dc.html frame 2) — collapsing shows a small accent dot on the icon so the hidden-but-active state isn't lost. The active-filter chip summary is untouched by any of this; it's a separate "what's applied" readout. BrowserFilter.dc.html now draws both active states (expanded-closable and collapsed-with-dot) side by side as the canonical reference.

Upload icon removed from the Glitter board

BrowserGallery.dc.html — Ryan-said: uploading is sticker-only. An earlier draft drew the upload button greyed/for-reference on the Glitter board too, which read as if Glitter supported uploads. Removed; the real, genuinely-visible button only lives in BrowserGalleryStickers.dc.html.

Spacing rhythm fixed in BrowserCategory.dc.html and BrowserMobile.dc.html

Uneven gaps between the filter-tag summary, description/attribution, and the grid — asymmetric padding (e.g. 2px one side, 4px the other) instead of a consistent unit. Standardized every stacked section to symmetric 8px padding so adjacent-block gaps read the same throughout both artboards; also brought BrowserMobile.dc.html's .searchrow padding (was 6px) in line with the 8px every desktop board uses for the same row.

On-device privacy note: dropped the card treatment

BrowserEmpty.dc.html's .privacy note had a bordered/filled box (background:var(--sunk);border:1px solid var(--border)) — Ryan-said it looked too much like the search box. Corrected to plain text (icon + tertiary copy, no box), matching .panel-note's real treatment elsewhere in the app.

Asset-browser parity pass across all nine artboards

Found and fixed real inconsistencies, not just style: (1) .abh .back was missing its :hover/:disabled rules entirely in BrowserEmpty.dc.html, BrowserGalleryStickers.dc.html and BrowserMobile.dc.html. (2) BrowserEmpty.dc.html had the back button's disabled STATE backwards in two of its three panels — disabled on a "User Uploads" (category-detail) panel where it should work, enabled on a "Glitter" root-search panel where it shouldn't. (3) The search-glyph and filter-glyph icon paths had drifted to slightly different coordinates in BrowserEmpty.dc.html only — same icons, redrawn differently; unified to the one path every other board uses. (4) .filterbtn was being redefined per-file (sunk/default in 4 files, accent/"active" in 3) instead of ONE base class plus a .filterbtn.on modifier like every other toggle in this system (.viewtoggle button.on, .item.on, .chip.on) — added the modifier everywhere, and unified the active-state label to "Filter · N" (was inconsistently "Filter · 3" / bare "2" / bare "3" across three boards).

Stickers drop the "By category / Show all" toggle

BrowserGalleryStickers.dc.html — Ryan-said: the sticker library is headed toward thousands of items eventually, where flattening the whole collection into one scrollable grid (the BrowserShowAll.dc.html pattern, fine for glitter/brush tips at their current scale) stops being usable. Removed the toggle for stickers; category browsing + search/filter is the one path there, not a visual-parity exception.

New artboard: sticker-context category grid

BrowserGalleryStickers.dc.html — the previous Browser artboards only ever showed the Glitter context (with the upload button drawn hidden/for-reference). This one is genuinely Sticker mode: real upload button visible, real categories from data/sticker-categories.json (Sparkle, Flower, Twitter, Decorative, Jewelry, Animal), single-icon tiles (not the glitter-only swatch montage), User Uploads pinned last.

New artboard: mobile drawer chrome

BrowserMobile.dc.html — three phone-width (390px) states: collapsed icon-only search on the category list, expanded/tinted search + single-row scrolling filter chips when a search or filter is active, and an armed picker session. Ryan-said (corrected after first draft): the header must stay the same shape — icon, title, collapse chevron, search/filter icon slots — in every view state, never reshaped or missing a control depending on mode; consistency across views outranks saving a row. First draft folded the picker title/detail into the header itself (replacing "Design", swapping the chevron for Done) — corrected so the picker strip stays its own row in the same position it occupies on desktop, only compacted to one line (title + Done, no detail subtitle) instead of merged into the header. See docs/PANEL-REDESIGN.md §10 "Mobile drawer chrome" for the code-level plan this draws from.

Attribution fixed to reuse the real component, not a lighter version

BrowserCategory.dc.html's category attribution went through two wrong drafts before landing: first invented phrasing ("Curated by X · license"), then a compact byline-only line with no card box. Both read as ad-hoc formatting rather than the app's one real attribution component. Corrected to reuse the literal SAME .credit box as BrowserBrushSet.dc.html (bordered card, uppercase "Source & usage" head, byline, dot-separated meta line) — the real Attribution.buildCreditElement shape, just omitting the archival-note disclosure and links row a category never has.

Stale armed-picker state removed from BrowserCategory.dc.html

The artboard was still showing the OLD picker strip armed by default, left over from before the header-consistency fix. Removed — this artboard's job is the normal browse view (description/attribution/filters), and the armed-picker state now has its own dedicated demonstration in BrowserMobile.dc.html frame 3.

On-device privacy note for User Uploads

New copy, no existing component: "Stays on your device — never uploaded to the site," pinned above the grid/empty-state whenever viewing user-uploads (uploads are genuinely local — handleUserUpload() in StickerManager.js only ever creates a blob: URL via URL.createObjectURL(), no network call). Closest existing precedent is .panel-note.

Parked — discussed, not in this design

Too involved or undecided. Kept here so they are not lost, not built now.

Saved styles / presets

Save a Fill + Border + Shadow combination as a named style and re-apply it. New storage + picker. Complex. Not now.

Stacked effects

Allow more than one Border / Shadow (a second shadow, an inner glow). Not now.

Copy source between paint slots

"Use same glitter as Fill" for Border / Shadow. Not now.

Blend mode on fills

Normal / Multiply / Screen / Overlay over the base. Undecided.

Eyedropper for Solid

Pick a color off the canvas for a solid source. Undecided.

Remove / replace — in the app now

Migrated deliberately, one work package at a time. No selector disappears in the same commit that introduces its replacement.

Eight label vocabularies

setting-label, effect-option-label, functional-control-group-title, advanced-control-group-title, control-group-label, settings-row-label-main all collapse to .property-label and .property-group-label.

Auto-collapsible cards

Every L2 card is currently made collapsible with an injected chevron. Becomes opt-in.

Per-slider "Reset" link row

Every slider gets a full-width <button>Reset</button> on its own third row (34 of them in the text panel). Replaced by the one revert icon in the row.

Free-form module summaries

"Solid, 2, 3, 35%" value dumps in collapsed headers. Replaced by one identifier.

Wrapping segmented control

Two segmented visuals exist (one-line and one that wraps). The wrapping one goes; large sets use a dropdown or .choice-grid.

Redundant title / label pairs

A card titled "Opacity" wrapping one row labelled "Opacity" (measured 120px tall for one slider). The block drops its title when it would equal the control's label.

settings-row-* modal vocabulary in the sidebar

Canvas Size is authored in modal markup and moved into the panel at boot. Re-authored in the row vocabulary (Canvas Properties + No-selection Size).

Five inconsistent empty states

Three use an icon-wrapper xl SVG, three use a literal emoji. Become one .property-empty component.

Filter sections are cards

Each .filter-section has a card background, radius, padding (six stacked cards in the drawer). Become label + chips separated by hairline dividers.

filter-label is a fourth uppercase level

Collapses into .property-group-label, the one uppercase level.

Nested scroll trap in the filter drawer

.filters-container-inner has max-height:200px; overflow-y:auto inside the already-scrolling panel. Removed; the panel scrolls.

Keep — in the app now, preserved

Asset dimensions and frame count

Reconsidered: staying. Useful, especially stickers ("512 x 512") and animated glitter ("12 frames"). One muted meta line under the name, not a metadata grid. Frame count + Animated badge only when frames > 1.

L0 accordion, one open at a time

The Y2K gloss bar (windows7-bar mixin) stays. This is where the era chrome lives.

Font picker

renderFontPicker() preview cards, sample rendered in the face. Unchanged.

buildAssetInfo component

Already one shared asset-summary component with a compact variant. Only styling / placement changes.

All element ids and manager bindings

Managers bind by id. Every stamped id keeps its legacy name; only structure and CSS change.

Image Size: Scale Textures / Scale Effects

Both toggles stay, under the Image Size mode of the Canvas Size control. Earlier draft wrongly implied they were dropped.

Category description

category.description already exists on every category and already renders in AssetBrowser.renderCategoryDetail() (e.g. the "twitter" sticker category) — the design just hadn't drawn it yet. Now shown in BrowserCategory.dc.html, detail view only, never on the grid tile.

Canvas Size: anchor grid + extension fill

The 9-cell anchor (canvasSizeAnchor) and the Transparent / Color extension with a conditional fill-color row stay, re-drawn in the row vocabulary.

Palette: Posterize and Dither branches

One module, one Mode switch. The mid rows swap between the two; both branches kept (Cleanup for Posterize; Algorithm / Color palette / Pattern / Shimmer for Dither).
