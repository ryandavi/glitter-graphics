Ryan-said: search/filter collapse to icons in the header on every board, desktop included — this used to be desktop-only-always-expanded / mobile-only-collapsed; now it's the one pattern everywhere. Default (this board): collapsed icons sit in .phead next to "Design", same slot every board uses; tapping either expands the full .searchrow in place below the header (pushes the grid down, never overlays it) and focuses it. Even when a search/filter is active, the user can manually collapse the row back to icons — the collapsed icon then shows a small accent dot (.icnbtn .dot) so the hidden-but-active state isn't lost. See BrowserFilter.dc.html for the expanded-active-with-close and collapsed-active-with-dot states side by side. — This board's header itself never changes shape between collapsed/expanded — same rule as the picker-strip fix: only the row below it changes, matching what already shipped in BrowserMobile.dc.html. — Ryan-said: no upload icon on this board — uploading is sticker-only (#uploadStickerBtn, [data-panel-mode="sticker"] .upload-sticker-action). An earlier draft drew it here too, greyed/for-reference, which read as if Glitter also supported uploads; removed. The real, genuinely-visible upload button lives in BrowserGalleryStickers.dc.html, the only context it ever applies to. — Category montage (4 swatches): today's schema only stores one icon string per category (createCategoryCard(), AssetBrowser.js) — there is no multi-thumbnail field. Needs a schema decision before this ships: either (a) an explicit curated thumbnails: [...] array admins fill in per category, or (b) auto-picked at render/save time from the category's own members (e.g. first N in stored order). Either way the same N items must show every time — never re-randomized per page load, or the tile looks different on every visit and stops reading as that category's identity. Same open question applies to the 3-example brush-set montage in BrowserShapesBrush.dc.html.
