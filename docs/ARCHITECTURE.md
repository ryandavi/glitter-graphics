# Architecture

A map of how the Glitter Graphics editor fits together. Referenced from `CONTRIBUTING.md`. It describes the system as it is. Planned changes live in the active plans in `docs/plans/` (local-only). Update this file as those changes land.

## Stack

- **Editor:** `index.html` plus plain browser scripts in `js/`. No framework, no bundler, no modules. Every file defines globals (`class Foo {}`, `function bar()`, `const BAZ = …`). Bundling is deferred for future work; the current app can be hosted directly on any static host.
- **Admin:** PHP and MySQL under `admin/`, run on local XAMPP. See `admin/README.md`.
- **Styles:** SCSS partials under `css/`, compiled to `css/style.css` by Ryan.
- **Asset data:** JSON manifests in `data/`, written by the admin export (see "Asset data" below).

## Boot sequence

1. `index.html` loads scripts in dependency order. Roughly: vendor libraries, then `js/core/releases.js`, `js/core/fields.js`, `js/core/config.js`, `js/core/layer-types.js`, `js/ui/panel-schemas.js`, `js/paint/paint-slots.js` and the layer-type definitions in `js/layers/types/` (each calls `registerLayerType`), then the rest of `js/core`, `js/effects`, `js/paint`, `js/transforms` and `js/ui`, followed by the `js/editor` method bags, domain classes in `js/layers`, `js/assets`, `js/export` and `js/systems`, and finally `js/app.js`. **Order matters:** a script can only use globals defined by scripts above it at load time. Put a new script tag after everything it depends on at the top level. Large optional payloads (`mp4-muxer`, the Preservation timeline data and `HtmlSceneExporter`) load on first use through `loadScriptOnce`. `tools/bump-cache.js` adds content hashes to local tags, lazy script URLs, worker URLs and worker `importScripts` dependencies.
2. `js/app.js` mixes the `js/editor/*` method bags (`EDITOR_SETTINGS_METHODS`, `EDITOR_PANEL_METHODS`, `EDITOR_FILL_TOOL_METHODS`, …) into `GlitterEditor.prototype` with `Object.assign`.
3. An async IIFE at the bottom of `app.js` loads the shape and brush manifests concurrently, then constructs `GlitterEditor`. Brush validation awaits shape definitions before applying its manifest. Generated fetch preloads start shapes, brushes and fonts after the stylesheet with low fetch priority; large browse indexes start concurrently during init to preserve CSS bandwidth. These manifests share `CONFIG.app.assets.manifestVersion` and use normal HTTP caching.
4. The constructor renders the sidebar from `PANEL_SCHEMAS` (`renderPanelSections`, then `renderTransformPanels`) and the context toolbars from `CONFIG.ui.contextToolbars`, then constructs the managers and subsystems. Managers may cache panel elements in their constructors, which is why schemas render first.
5. `editor.init()` creates the exporters, then initializes the independent layer controllers and asset browsers concurrently. Indexes and font preview icons stay at boot because the Library immediately renders category previews. Boot marks (`glitter:scripts-parsed`, `glitter:manifests-loaded`, `glitter:constructor-done`, `glitter:init-done`, `glitter:editor-ready`) are recorded by the IIFE; `tools/load-report.js` reports cold/warm load timings both unthrottled and with simulated Fast 4G and 4× CPU throttling.
6. `window.editor` is the live instance, which is useful in DevTools and headless probes.

## Who owns what

Background removal is an optional action on uploaded, static PNG/JPEG sticker layers. `StickerManager` checks eligibility and lazy-loads `js/systems/BackgroundRemover.js`; its worker owns ONNX Runtime Web and ISNet inference. Nothing downloads at boot. WebGPU is tried first, then single-thread WASM; Cancel terminates the worker. Processing uses the shared TaskProgressPresenter and export progress card styles, including indeterminate animation, timing notices and Cancel. The modal opens only after processing and previews Before/After on a checkerboard. Keep registers a new upload and swaps the captured layer's source while preserving transform and effects, then saves one history step. The original stays available. Generated cutouts carry a backgroundRemoved flag, embedded in saved projects, and are ineligible for repeat removal. Existing project embedding and export paths handle the cutout PNG. Downloads use a pinned model revision and Cache Storage where available; the image stays on-device. `CONFIG.tools.backgroundRemoval.enabled` disables the action. Runtime/model licenses and provenance live in `js/vendor/background-removal/README.md`. The worker releases inference memory after two idle minutes.

The `GlitterEditor` instance (`editor`) holds every subsystem. Two kinds of `*Manager` exist; see the `js/` naming notes in `CONTRIBUTING.md`.

Shared math and color helpers live in `js/core/math.js` and `color.js`, usable in classic scripts, workers and Node. `loadImageElement` in `dom.js` waits for decoding before returning; mask swaps retain their previous URL until this completes. Vector brush rasterization and its cache live in `js/paint/brush-stamp.js`. Context toolbar entries declare `when(editor, context)` predicates in CONFIG.

Every glitter paint uses `SlotGlitterPicker.applyPick`; mixed asset pickers retain their own browse UI. `PickerRegistry` owns the shared Close button and one active owner. The armed session is the Library's one readout: its `library` (glitter for a paint slot) is the asset kind shown, and its slot or `label` is the Library's title (`syncPickerTarget`, `describePickerTarget`, `js/ui/picker-session.js`); which layer is the Inspector's bar to say. Every session is `{ kind: 'paint' | 'asset', layerId?, slot?, library?, label? }`, and a paint session always names a real slot key. A session tied to a layer ends when another layer is inspected or its paint is gone from the layer (`closeStale`); undo keeps a session that still holds. A paint is armed through its type's field host (`editor.armPaintSlot`), never by pressing a control. A Library pick changes the selected layer and never adds one. A glitter pick needs a selected layer; with none it only reports that. The Library window (`LibraryWindow`, `js/ui/library-window.js`) shows the open `PickerRegistry.flyout` section and/or the active asset session. Desktop places it over the canvas beside the Inspector; it never refits the view or folds Layers. Phone presents the same window as a sheet, with a section and its asset Library as separate pages joined by Back. Flyout cards stay in their one host and existing bindings survive. Picks report the type and paint slot. Manifest `swatchCount` makes recolor eligibility synchronous; GIF loading and palette analysis happen only for the chosen asset.

## Layer data model

Every layer has `id`, `type` (a `LayerType` value), `name`, `visible`, `locked` and `opacity` (0–100, the only whole-layer opacity; nothing mirrors it). Movable layers also have `transform`, and optionally `blendMode` and `animations`. Type-specific data lives under one key:

| `LayerType` | Data |
|---|---|
| `base-image` | `background`: the fill slot |
| `glitter-fill` | `selections` (color-picked regions), `settings` (threshold, feather, invert, contiguous, multiSelect), `fill`, optional `border`/`shadow`, `maskVersion`, `transform` (places the canvas-sized mask surface; the mask, selections and brush strokes stay in that surface's own px) |
| `sticker` | `stickerData` (custom serializer in `StickerManager`) |
| `text-glitter` | `textData`: text, font, layout, `fill`, `border`, `shadow`, `bevel`, `textBackground` |
| `shape` | `shapeData`: `shapeId`, size, `fill`, `border`, `shadow`, `bevel` |
| `path` | `pathData`: `subpaths`, `fillRule`, `fill`, `stroke`, `border`, `shadow`, `bevel`, `sparkles` |
| `filter` | `filterData` |

**Paint slots.** `fill`, `stroke`, `border`, `shadow`, `bevel`, `sparkles` and the text background's `fill` are "paint slots": a source mode (`none`, `solid`, `gradient`, `glitter`, `image`) plus color, gradient, glitter id, scale, opacity, color adjust and texture offset. Every slot is one self-contained object. Each layer type declares its slots once, back to front, in its `paintSlots` list (key, role, path on the layer, draft path, default glitter, panel id prefix, source modes, editable fields). `js/paint/paint-slots.js` owns the concept:

- `getLayerPaintSlots(layer)` lists a layer's slots with their data and whether each is present and renders. `getLayerFillSlot(layer)` returns the fill slot whatever the type. Preloading, document scaling, the Effects badge, export culling and project-load glitter repair all iterate this list instead of naming slots per type.
- `resolvePaintSlotSource` turns slot data into a render source (through `resolveEffectPaintSource` in `js/paint/effect-source.js`). Preview uses `resolvePaintSlotPreviewSource`, which adds only a live check that the glitter is in the library.
- `buildSlotStack(layer, resolveSource)` returns the slots to draw in paint order. It holds the one ordering rule: a border drawn in front moves after the fill. The preview span stack and the export compositor both read it.
- `applyPaintSourceToElement` is the one DOM painter for a resolved source: text and shape spans, the sticker shadow, the glitter fill and the canvas background.

**Editable fields.** A type's `fields` and its slots' fields are bindings: a data path plus a `FIELDS` spec. One declaration drives the control's range and default, the slot's default value, document rescaling (`documentScale`, read by `js/core/document-scaler.js`) and the panel binding. `bindFieldControls(host)` / `syncFieldControls(host, layer)` in `js/ui/paint-slot-controls.js` bind and sync every declared control by id (`panelPrefix` + suffix for slots): sliders, number fields, checkboxes, source modes, glitter chips, colors, effect toggles, border options, texture position and the gradient editor. The Fill, text, shape and sticker managers supply only a host that says how their layer re-renders and records history. `syncSlider` in `js/ui/slider.js` is how any other code shows a programmatically set slider value. Number-pair marks use the same numeric step math and live-apply scheduler to scrub with mouse or pen after 3 px of horizontal motion (one value unit per pixel, Shift ?10, Alt ?0.1, respecting the field's grid and bounds). Pointer capture keeps the drag on its intended field; release commits once, while Escape or pointer cancellation restores the starting value without history. Touch retains plain-label behavior.

The Posterize and Dither filter looks and Auto Glitter share the `paletteColorCount`, `paletteMerge` and `paletteDetail` field specs plus the `analysisPaletteStyle` option registry; `GlitterPixelEffects` and `palette-analysis.js` are the shared engines. Canvas-wide pixel effects are filter layers above the canvas, using the same operation registry as other filter looks.

**Layer animation.** Animatable layers store an ordered `animations[]` stack. Each entry is one normalized motion preset with its own timing, easing and parameters. The editor allows up to `CONFIG.tools.animation.maxStackSize` entries (currently 3), while loading keeps extra entries from newer project formats intact. `GlitterAnimation.sampleAt` samples every entry on the shared document clock and composes their affine transforms in stack order, multiplies opacity and adds hue. Preview and export consume that same composed sample. Export registers one timeline source per entry so motions with different periods can be planned without flattening their clocks.

Pause motion freezes the canvas preview, including animated glitter in every paint slot, image fills, stickers, frame images and procedural motion. `AnimationPanelController` caches static first-frame URLs while paused; shared paint sources and image renderers resolve their preview URLs through it. Resuming clears the cache and restores original animated URLs. Layer data and export sources never receive the preview URLs, and assets added or changed while paused follow the same resolver.

**Sparkles.** `sparkles` is a paint-slot role: a slot scatters small animated glyphs over its host layer (sticker, text, shape, fill layer, frame and the canvas each declare one, and the Sparkles layer type is nothing but one canvas-sized slot, for weather in front of everything). `js/paint/sparkles.js` owns the concept: `SPARKLE_GLYPHS` (the particle shapes), `SPARKLE_PRESETS`, a seeded layout (`computeSparkleLayout`, emitter `inside` scatters over the host's opaque pixels, emitter `edges` follows the host's outline (its box edge when it has no pixels), emitter `highlights` is Kira Kira and puts one star on each highlight that `js/effects/highlight-detect.js` finds), and per-frame sampling (`sampleSparkleFrame`). Particle motion comes from the motion library: every `MOTION_REGISTRY` entry with a particle target is a sparkle behavior, and each particle does a whole number of cycles per slot cycle, so GIF loops close. Fall and rise are particle-only wrapping motions. The sampler passes each particle's emitter area and visual box to the shared pose, without branching on motion ids. A type supplies its pixels through `sparkleHost(editor, layer)` on its definition; layouts and host pixels are cached per content key. Preview reconciles a `.sparkle-layer` of masked spans inside the host element (`reconcileSparkleLayers`) and `AnimationTicker` repaints it through the target's own `paint`; export draws the same layout with `drawSparkleFrame` into the host's surface, and each slot registers one procedural timeline source through its type's `timelineSources`. `buildSlotStack` leaves sparkles out: they are particles, not a masked surface.

**Distance-field effects.** `js/paint/mask-geometry.js` owns the exact Euclidean signed-distance field and round dilation/erosion used by borders, sticker outlines and shadow spread; `createShadowMaskCanvas` also fades a shadow's edge over its Blur px from that field (a soft glow at offset 0), so the fade is identical in preview and export. A transparent GIF can only keep or drop a pixel, so when a layer has a blurred shadow `GifEncodingPipeline` dithers alpha below its cut through a fixed Bayer pattern instead of dropping it (`transparency.ditherSoftEdges`). Hard borders retain four-neighbor morphology. Outline slots can fill enclosed transparent counters by flood-filling edge-connected transparency and adding only the unreachable regions to the outline mask. `js/paint/bevel.js` derives soft inner highlight/shade masks from that same field for the Smooth, Chisel, Pillow, Emboss and Gloss profiles; its scale-aware Sobel normals smooth lighting across raster contour steps without softening the thresholded silhouette. Those soft inner masks are intentionally not binarized, so transparent export edges stay crisp. Text and shape preview/export consume the same manager mask callbacks. Sticker effects rasterize at the displayed box size; animated sticker outlines use the union of all frame alpha by default, and can retain the silhouette interior to act as a backing plate.

**Shadow geometry.** Every shadow slot stores `kind: 'drop' | 'extrude' | 'cast'`. `createShadowSlotMaskCanvas` is shared by all four shadow-bearing managers and sticker export. Extrude sweeps the spread/blur silhouette in whole-pixel steps to Offset X/Y. Cast projects a separate silhouette onto a floor behind the artwork: its chosen anchor stays fixed, and its top projects upward by `castLength` and sideways by signed `castLean`, in physical pixels for non-text artwork. Text stores `castLengthRatio`, `castLeanRatio` and `castBlurRatio`, shown as percentages of font size; `castSize` in the mask metadata resolves them through the committed horizontal/vertical raster scale. These ratios remain unchanged during transform baking and document resizing, independent of Scale Effects. Only the shadow copy is compressed/sheared; the artwork mask stays unchanged. `_shadowBounds` carries the artwork box and optional text baseline independently of mask padding and follows vector raster scale. Text defaults to `castAnchor: 'baseline'` and offers Baseline / Bottom edge; other artwork defaults to Bottom edge. Multiline text uses the last ink line, and warped text uses its lowest placed glyph baseline. Length zero paints no cast. Cast defaults to Blur 0; optional Blur fades the projected mask afterward in physical pixels (text softness resolves from its font size and the geometric mean of the raster scales) through the shared distance-field builder. Bounds include that fade, and transparent GIF export dithers its soft alpha. Offset and Spread remain hidden while their settings are stored for the other kinds. Text defaults are Length 25%, Lean -70%, Blur 0%; other artwork keeps Length 16px, Lean -45px, Blur 0px. `getShadowSlotOffset` returns zero for Cast and Extrude, and `getShadowSlotBounds` reserves the projected/swept reach for text/shape allocation, fill visual bounds and sticker padding. Side lighting remains a separate future feature.

**Paths.** A path layer (`js/layers/PathLayerManager.js`) is Bézier geometry painted with a fill and a stroke. `pathData.subpaths` is a list of `{ closed, points: [{ x, y, in, out, type }] }`: `in` and `out` are handle offsets from the anchor or `null`, a segment is straight when both of its handles are `null`, and `type` is `corner`, `smooth`, `mirrored` or `auto` (handles derived from the neighbouring points, re-solved whenever they move). `PathGeometry` (`js/paint/path-geometry.js`, DOM-free) is the one home of the curve math: evaluation, tight bounds, flattening and length, nearest point, fill and stroke hit tests, point insertion and deletion, segment dragging, trimming, and SVG path data in both directions (arcs and quadratics become cubics). Rendering, picking, the point editor and ornaments all call it.

Points are stored in layer-local px around the origin `layer.transform.position` places. After every geometry change `recenterLayer` moves the points back around the origin and moves the position by the same offset through the rotation and flip, so nothing shifts on canvas. The offset lands on whole pixels while position rounding is on, which keeps anchors placed on whole pixels there. A finished resize is baked into the points (`commitScale`), so masks are always drawn at 100% and a live drag only CSS-scales the stack. Stroke width, dashes and effect sizes follow a resize by how much the geometry itself grew: a line stretched across its thin axis did not.

`stroke` is a paint-slot role: the line the path is drawn with, switched on and off like an effect (its settings park in `effectDrafts`). An open path defaults to a stroke and no fill, a closed one to a fill and no stroke. The **body mask** is the fill united with the stroke, each only while it renders, so with fill None the body is the line alone. Outline, shadow, bevel and sparkles are raster effects of the body (`createBorderMaskCanvas`, `createShadowSlotMaskCanvas`, `createBevelMaskCanvases`), the way text derives them from its glyph mask: an outline wraps both sides of a line, and Smooth, Sharp and Pixel edges and every placement work with no path-specific code. The layer's `frame` is the body's painted bounds plus the outline, so a horizontal line has the stroke's height.

`js/paint/stroke-mask.js` is the only place a path and its stroke become pixels. `planStrokeSubpath` (DOM-free) decides which part of an open subpath is stroked and where its end ornaments go; `buildStrokeMask` draws the plan (width, Smooth or Sharp joins, cap, dashes) and thresholds it. An ornament is a shape from `data/shapes.json` whose `uses` include `ornament`, with `ornament: { tip, anchor, trim, angle }`: it is pinned to the endpoint by its tip or center, turned to the end tangent, sized as a multiple of the stroke width, and filled into the stroke mask, so the stroke's paint runs unbroken into it and every body effect includes it. The stroke is trimmed beneath an ornament by `trim` of the ornament's size, then dashed, with the dash phase shifted by the trim so adding an ornament does not slide the dashes. A path shorter than its trims keeps its ornaments and draws no line. `STROKE_PRESETS` (Line, Arrow, Dotted…) set only the dash style and ends.

A path is far thinner than its element (the padded mask surface), so the type is `pickedOnCanvas`: the element takes no pointer events and `hitTest` answers from the geometry (inside the fill, or within the stroke and outline of the line). `PathLayerManager.createLayer({ subpaths, stroke, fill, name })` takes canvas-space geometry and is the one entry point for the Line tool, the Pen, Convert Shape to Path (`convertShapeLayer`, built on `ShapeLibrary.getSubpaths`) and tests. Shape and path share their mask plumbing in `js/paint/mask-surface.js` (padded mask allocation, the measurement cache, preview mask URLs).

**Edit sessions.** `editor.getActiveSession()` names the session that owns the canvas and keyboard: `textEdit`, `pathEdit`, `crop` or `null`. Context toolbars with `session:` show for it, and commands gate on it. `PathEditSession` (`js/ui/path-edit.js`, `editor.pathEdit`) is the Pen's session. It edits a set of subpaths in canvas px through a host (`{ layerId, getLayer(), read(), write(subpaths, { label, coalesceKey }) }`; `PathLayerManager.createEditHost` supplies one) and holds only the layer id and point addresses, re-read by `revalidate()` after every history restore and visibility or lock toggle. Its `draw` mode appends points to one end of an open subpath; `edit` selects, moves and reshapes them. The path is a real layer from its first point (created without a history step); history starts at the second point, then each placed point, completed drag, insert and delete is one `saveState`, and nudges coalesce. Discarding an initial one-point path records no history. During a drag the geometry lives in the session and the chrome follows every frame; the painted layer follows too until one redraw overruns `CONFIG.ui.live.rasterBudgetMs`, after which that drag moves the chrome only and the layer is redrawn on release. The Pen declares `onActivate` / `onDeactivate`, which the temporary Hand (Space) does not trigger, so panning never ends a path. `PathChrome` (`js/transforms/path-chrome.js`) draws the outline, anchors, handles and next-segment preview as one SVG in `SelectionOverlay` with one syncer and no pointer events; the session hit-tests through it from the screen numbers it last drew.

**Frames.** The Frame layer type (`js/layers/FrameLayerManager.js`) is a border around the picture. `js/paint/frames.js` owns its registries: `FRAME_KINDS` (`style`, a ring painted with the frame's `fill` slot, or `image`, a frame-category sticker fitted to the box), `FRAME_STYLES` (CSS's border styles as band tables: slices of the ring's thickness with a shade per side, sides meeting at the corner diagonals) and `FRAME_PRESETS`. `buildFrameShadeMasks` splits the ring into one mask per shade, and `shadeFramePaintSource` shades the fill for each (solid and gradient colors directly, glitter through its color adjust brightness), so the preview span stack and the export slot stack (`_buildSlotStackExportPlan` with the frame's `buildStack`) paint the same bands. A pinned frame (the default) derives its box and transform from the canvas on every read (`syncPinnedGeometry`) and is not transformable, so it follows canvas resizes and lets clicks through; unpinned, it keeps its box and bakes resizes into it like a shape.

**Gradient presets.** `js/paint/gradient-presets.js` registers one `GRADIENT_PRESETS` library used by every shared gradient editor. Presets are copied into the paint slot and are not serialized by id. Their thumbnails and rendered layers both pass through `effectGradientToCss` / the shared effect-gradient stop expansion, preserving preview/export parity.

**Text warp.** `textData.warp = { type, bend }` bends where glyphs are placed in the text mask, so every slot drawn from that mask (border, shadow, bevel, sparkles) bends with the text, and preview and export share it through the one mask canvas. `js/paint/text-warp.js` owns `WARP_TYPES` (`none`, `arc`, `arch`, `sag`, `bow`, `chevron`, `peak`, `rise`, `taper`, `climb`, `ripple`, `wave`, `flag`, `bulge`; Arc at 100% is a full circle; each has a DOM-free `layoutGlyphs(glyphs, bend, metrics)` returning a placement per glyph) and the `WARP_PRESETS` grid. There are two kinds. Placement warps (`arc`, `wave`, `flag`) move, turn and stretch whole letters. Envelope warps (every other type) also declare `envelope(u, bend) -> { top, bottom }`, how far the block's top and bottom edges move across its width: the mask is drawn flat and pushed through the envelope in one-pixel columns (`drawThroughWarpEnvelope`), so the letter outlines themselves bend, and their `layoutGlyphs` is the same warp one letter at a time, which carets, Split and line boxes read. `TextGlitterManager.getMeasurementEntry` measures the flat layout first, then, for an active warp, lays glyphs out one by one around the flat block's center and rebuilds the ink, the per-line rects (Text Background) and the frame from the warped glyph boxes; warped point text's body hugs its ink. A warp that changes nothing (`none`, or bend 0) keeps the flat drawing path, so unwarped text keeps its exact pixels. A tile is only a type plus a starting bend (Arc and Arc Down are one type), and `matchWarpPreset` names the tile a tuned warp belongs to (nearest preset of the same type and direction, or of the type alone when it has one tile, flagged `modified`), so the grid and the Warp card header never lose the type.

**Style presets.** `js/paint/style-presets.js` registers one `STYLE_PRESETS` library per target type (text, shape, sticker). An entry is a partial paint-slot bundle keyed by slot key (plus plain `data` field paths, e.g. a text preset's font); a shared look keeps only the slots its target declares. Applying one owns the fill, border, shadow and bevel slots: named slots are switched on and reset to their defaults plus the preset's values, effect slots it leaves out are switched off (parked as drafts), and a left-out fill is kept. It runs through the type's field host as one edit, so one history step. `findStylePresetId` recognizes a layer that still matches a look, for the grid's active tile; anything else reads "Custom" in the Style card header. Text and shape tiles are real renders (`js/ui/style-preset-thumbnails.js`: the look applied to a throwaway sample layer, masks from the manager's `renderSlotMasks`, painted back to front like `SceneCompositor`); sticker tiles stay a CSS sketch. The text-only WordArt group has 28 looks using the same slots and warp masks, including cast shadows and extrusion. The recipes use installed Arial, Arial Black, Times New Roman and Impact faces. Paper Bag uses Office texture 417; Texture Stack uses granite 427, both anchored to the layer through the existing glitter pipeline. Green Marble remains flat green. Marble Slab and Gray Block await a lit perspective extrusion engine; Superhero and Stack 3D use flat extrusion approximations. Text styles reset font id/weight/style, case, orientation, decorations, letter spacing, line height and warp type/bend before applying their values. Missing font and warp values use the app defaults. They replace the entire fill with defaults plus the recipe, clear background, sparkles, animations and parked effect settings, and restore layer opacity and blend mode. Text content, font size, box layout and placement are preserved. Presets never change placement or transform scale. `createStylePresetEntryFromLayer` copies enabled style slots with their non-default values plus these text paths; the debug-only Copy style as preset command writes a registry entry to the clipboard.

**Canonical state.** A layer is normalized once, where it enters the document: its manager's `createLayer`, `LayerManager.deserializeLayer` (undo/redo, clipboard, project load, cloning) through `LAYER_UI_CONFIG[type].serialization.normalize`. Getters and render paths read the canonical shape and never write defaults. Pre-launch files use format 6 without backward compatibility: the migration table is empty, and older versions fail with the missing-migration error. Format changes update both shipped templates in the same change. At launch, reset the format and templates to 1 and begin versioned migrations for subsequent format changes.

**Transforms.** Movable layers (sticker, text, shape) keep a transform `{ position, rotation, scale, flipX, flipY }`. It lives only at `layer.transform`; `getLayerTransform(layer)` (`js/transforms/transform-math.js`) reads it and returns an unstored identity placement for types without one. Scale writes go through `LayerTransform.updateTransform`, which clamps with `clampLayerScale`. `resolveAspectLock` decides whether a scale drag is proportional: the stored lock, flipped by Shift for that one drag, on corners and edges alike. Constrained scaling multiplies both gesture-start scales by the same factor, preserving the current proportions. A Shift drag that leaves a locked layer with different proportions turns the stored lock off at release (`scaleDragBreaksAspectLock`); Shift making an unlocked layer scale proportionally stores nothing. Linking X and Y again keeps the proportions the layer has. Single-layer, group and sidebar resizes call the same manager method, `commitScale(layer, startScale)`. The shared field walkers in `document-scaler.js` scale enabled slots and parked effect drafts by their declared class. Outline, shadow, bevel and sparkle dimensions follow Scale Outlines & Effects; texture dimensions follow Scale Textures; shape and frame radii follow Scale Corners. Text background padding, radius and merge distance always follow the baked font size, as letter spacing does. Frame thickness stays in pixels when baking its box. Canvas resizing scales every declared class unconditionally. `collectSnapTargets(kind)` reads `CONFIG.snapping.targets`: moves use canvas and layer edges/centers, scales use canvas edges, text boxes may also use their own ink edges, and path points use canvas and layer edges/centers plus alignment with their own path's other points. Constrained corner points project onto their resize diagonal before target testing.

**Layer descriptions.** Type definitions provide optional `describe(layer, editor)` and `defaultCreateOptions(editor)` hooks. Shared layer-list and selection status code read the same `{ name, detail }` description; the status is `Selected: <name>`. Panel loading dispatches to `manager.loadLayerSettings`; glitter picker selection uses `resolveSelectedGlitterId` or the manager’s slot picker. Animation prefixes come from the type’s `transformPrefix`.

**Fill tool.** `js/editor/fill-tool.js` owns color picking and its context controls. It resolves the active Fill layer, otherwise the topmost Fill layer in the hit stack, otherwise creates a Fill layer when allowed. Selection fields use the shared field binder, preserving live threshold reselection, context mirrors and one history commit per completed edit.

**Layer frames.** Each movable type declares two layer-local boxes on its `registerLayerType` definition, read through `getLayerFrame` and `getLayerVisualBounds`. The `frame` is the object's body (content, border and background plate, no shadow); handles, click hit-testing (`LayerManager.isPointInLayer`), alignment, snapping and group bounds use it. `visualBounds` adds the shadow and covers every painted pixel; export culling and crop-to-artwork use it.

**Canvas selection.** `isLayerSelectableOnCanvas` admits visible unlocked layers with transform capability or a registry hit test. Selecting a pinned frame shows read-only selection chrome; starting a drag still requires transform capability.

**Settings ownership.** `PREFERENCES` / `PREFERENCE_SCHEMA` own runtime preferences, including hints, destructive-action confirmation, welcome visibility/last-seen release and transform scaling. Consumers read the store directly. `glitterEditorSettings` contains export settings only. The theme setter alone writes `glitterEditorTheme`, which the inline first-paint script reads. Panel widths, card state, toolbar placement and brush settings retain their module-owned keys and reset hooks. Reset Everything resets preferences and invokes those hooks.

**Settings modals.** The Export Settings and Settings modals render from `EXPORT_SETTINGS_LAYOUT` and `APP_SETTINGS_LAYOUT` (`js/ui/settings-store.js`) through `js/ui/settings-renderer.js`. Export rows take their label, description and control from their `EXPORT_SETTINGS_SCHEMA` entry. Custom widgets (the type and format controls, the GIF Look preview, the fidelity slider, the HTML Scene group) are `<template>`s in `index.html`.

**Paint-mask handoff.** A committed stroke keeps its live overlay until the matching full-resolution mask image has decoded and replaced the displayed mask. Existing mask URLs stay displayed while new masks encode; draft downsizing is used only before a layer has a usable mask URL.

**Memory.** `getMemoryBudget()` (`js/systems/MemoryLedger.js`) returns this device's byte budgets from `CONFIG.memory` (a smaller set on iOS and devices reporting 4 GB or less). Undo history trims its oldest steps past the history budget, keeping `minHistorySteps`; paint history evicts past its own budget; rebuildable preview caches are `ByteBudgetCache`s that share one LRU budget; an animated GIF export asks first when its estimated peak memory exceeds the export budget.

**Handle gestures.** Handle drags are relative to the grab point: nothing changes until the pointer travels `dragThresholdPx` screen pixels, scale handles follow the pointer's movement from the true frame corner, and rotation adds the pointer's change in angle around the frame center (Shift snaps to 15°). Selection chrome is sized in screen pixels, outside the zoomed canvas.

## Touch and canvas input

Canvas input has two pipelines, split by `pointerType`.

- **Touch** goes through `GestureManager` (`js/systems/GestureManager.js`, owned by `ViewportManager` as `editor.viewport.gestureManager`). It listens on the preview container in the capture phase, sets `touch-action: none`, captures each pointer, and stops the event, so no element handler below ever sees a touch it took.
- **Mouse and pen** return early from `GestureManager` and use the element handlers: `LayerTransform.setupMouseDrag` on each layer element, the preview-container `pointerdown` in `js/editor/canvas-gestures.js` (marquee, canvas-picked layers, a tool's own `onCanvasPointerDown`, creation drag, scrubby zoom) and its `dblclick` (a type's `onDoubleClick`), and `wheel` plus Safari `gesture*` events for trackpad zoom and pan (`VIEWPORT_INPUT.normalizeWheel`).

Both pipelines end in the same places: `LayerTransform` / `GroupTransformManager` for layers, `ViewportManager` for the view, `MaskEditor` for the brush, and the `beginCreationGesture` family for tools that drag out a box.

**What `GestureManager` leaves alone.** A touch on `.ui-ignore-gestures` is ignored. A first touch on the selection chrome (`.transform-handles`) is handed to the chrome: a handle element takes it through its own `pointerdown`, and a touch on the bounding box is run through `SelectionChrome.hitTest`, which starts `beginHandleDrag` when it lands in a handle's hit square. Handle drags run on document-level pointer listeners keyed to one `pointerId`, outside the gesture state machine. A second touch joins an existing canvas gesture even on a handle; during a handle drag, additional canvas touches are ignored. Anything new drawn over the canvas needs `.ui-ignore-gestures` or it will be treated as canvas.

**State machine.** `idle → pending → dragging`, or `→ twoFinger` when a second touch lands. At most two pointers are tracked; a third is ignored, and so is a second contact that `isLikelyPalmContact` judges to be a palm (contact box at least `palmRejectionContactPx` on its long side; devices that report no contact geometry are never judged).

- `pending` becomes `dragging` once the finger passes `tapSlopPx`, held back until `secondFingerGraceMs` has passed or the finger has travelled `secondFingerCommitSlopPx`, so a pinch whose fingers land a moment apart does not start as a drag.
- A release inside `tapSlopPx` and `tapMaxMs` is a tap. Two taps within `doubleTapMs` and `doubleTapSlopPx` are a double tap: text edit on a text layer, zoom in (or fit, from 4x and up) on empty canvas.
- Lifting one finger of a two-finger gesture continues as a one-finger drag of the same target.
- `pointercancel`, lost capture, window blur and tab hide all end the gesture through `cancelActiveGesture`.

All thresholds are in `CONFIG.ui.gestures`.

**Routes.** The route is resolved once per phase and decides who receives the movement.

| Fingers | Route | Chosen when | Goes to |
|---|---|---|---|
| 1 | `brush` | Brush tool | `MaskEditor.handleTouchPan` / `handleTouchTap` |
| 1 | `groupDrag` | Select tool, multi-selection, touch inside the group bounds | `GroupTransformManager.dragByScreenDelta` |
| 1 | `layerDrag` | Select tool, top layer under the finger is transformable and unlocked | selects it when the drag starts, then `LayerTransform.dragByScreenDelta` (snapping applies) |
| 1 | `layerSelect` | Select tool, top layer is selectable but not transformable (a pinned frame) | tap selects; a drag pans |
| 1 | `creationDrag` / `tapCreate` | the tool's `touchRoute` in `TOOLS` | `beginCreationGesture` family, or `handleWorkspaceAction` on tap |
| 1 | `toolDrag` | the tool's `touchRoute` in `TOOLS` (the Pen) | the tool's `onTouchDragStart` / `Move` / `End`; a tap goes to its `onCanvasAction`. A second finger cancels the drag (`onTouchDragCancel`) and pans or zooms instead |
| 1 | `viewport` | everything else | `ViewportManager.panBy`, then inertia on release |
| 2 | `brushViewport` | Brush tool | cancels the stroke, then pans and zooms the view |
| 2 | `groupGesture` | Select tool, multi-selection, the midpoint inside the group bounds or one finger inside bounds grown by `layerGesturePaddingPx` | `GroupTransformManager.applyGestureDelta` |
| 2 | `layerGesture` | Select tool, the midpoint inside the target frame or one finger inside its padded frame; target is the first finger's `layerDrag` layer or the active layer | selects the target before `LayerTransform.applyGestureDelta` |
| 2 | `viewportTwoFinger` | fingers away from the target | `ViewportManager.transformByGesture` |

A one-finger drag that upgrades to the matching two-finger route (`layerDrag → layerGesture`, `groupDrag → groupGesture`) keeps one interaction and one history step. Any other upgrade commits the first route before the second begins.

**Two-finger math.** Each move sends an incremental composite `{ scale, rotateDeg, centroid, previousCentroid }`. For layers, the layer position is scaled and rotated about the previous centroid and re-placed at the new one, so the point under the fingers stays under them. For the view, the canvas point under the previous centroid lands under the new one. A pinch scales both axes by one factor whatever the aspect lock says. There is no snapping, rotation detent or badge on this path.

**Committing.** `beginGestureInteraction` records the start scale; `endGestureInteraction` bakes a changed scale the same way a corner handle does (`commitScaleChange`) and calls `saveState` once. `editor.touchGestureActive` is true while a gesture runs, and `LayerManager.handleLayerPick` refuses to pick during it. A click that follows a handled tap is swallowed for 400 ms.

**Touch selection chrome.** On coarse pointers handle hit squares grow to `handleHitSizeCoarse` (44 to 48 px), resize hit squares shift outward by `handleHitOffsetCoarse` while the visible handles stay put, the inner move zone is tested first, the corner rotate zones are dropped in favor of the rotation stalk, and handles that span a side shorter than `touchMinHandleSpan` are hidden so a small layer can still be grabbed by its body.

**Inspector.** `editor.refreshInspector()` (`js/editor/panels.js`) is the one way the Inspector follows the editor: which panels show, their values, empty states, the lock state, the header, and pickers armed for another layer. Selection, tool changes, undo, project load, a layer made by a tool and edit sessions all call it. `editor.getVisiblePanels()` is the ordered list of panels by `sectionPrefix`: the tool's own panel (`TOOLS[tool].panel`) leads, then the active session's (`SESSIONS[*].panel`) or the selection's. The panel switch and the phone chip bar read that list, so a tool with a panel is one `TOOLS` line. A section's state (summary, swatch, switched off, switch, the source mode of each of its paints) is read from its controls by `readSectionState` and announced as one bubbling `sectionstatechange` event from the section's card (`syncSectionState`, `js/ui/panel-renderer.js`). Managers write the DOM without events, so each section has one observer that turns those writes into the event; the Inspector's line, the phone chip and the Library window's bar listen for it and read the same object, and none of them reads another's rendered output.

**Mobile shell.** `MobileManager` turns on at `CONFIG.ui.mobile.breakpoint` (1040px); the Sass copy in `css/_mixins.scss` is checked by `script-globals-unit`. The permanent bottom bar derives its chips from `getPanelSectionIndex` over the same rendered schema hosts the Inspector uses. Layers remains a sheet; inline sections narrow the Inspector to one section and flyout or asset sections use the Library window. No `mobileSettingsSections`, Edit drawer, unarmed Library or panel reparenting remains. New layers read the type's `openOnCreate` target. Sheets open at half height or their last session height, stop widening at 640px, and support native content scrolling, downward-pull handoff, peek/half/full detents, velocity dismissal, grabber arrows and Escape. A Library's Back returns to its originating section. Drawing tools suspend canvas actions while the rail is hidden; Select and viewport gestures remain available. Closing restores the prior view while preserving the user's pan/zoom. `ViewportManager.getUsableRect` calculates fitting space without resizing the workspace: desktop fits between Layers and the Inspector (or the Library window while it is open), phone fits above its nav and sheet. `MobileManager` owns sheet state and history; the chip bar is `PhoneChipBar` (`js/ui/phone-chip-bar.js`) and each sheet's drag gesture is `bindSheetDrag` (`js/ui/sheet-drag.js`). `viewTween.shown` supplies canvas and selection chrome transforms in the same frame, using the sheet's easing and duration. The pixel-zoom debounce skips active tweens. Reduced Motion disables both animations. The phone rail is collapsed to its tool switch, Undo and Redo until the switch opens it; the Hand stays among its tools.


**Tests.** `tests/ui/touch-smoke.js` drives real multi-touch through CDP and `tests/ui/touch-handle-verify.js` covers handle drags; `tests/unit/gesture-manager-unit.js` unit-tests `GestureManager` without a browser. See [tests/README.md](../tests/README.md).

## Render path (live preview)

Preview is DOM, export is canvas. Every visual feature exists twice, and the two must match.

1. Code that changes what's visible calls `editor.requestPreviewUpdate()`. It coalesces to one `requestAnimationFrame`. Don't call `updatePreview()` directly.
2. `updatePreview()` reuses the processed base-canvas pixels when the background signature is unchanged, then iterates the registered layer managers and calls each one's `renderContent(visibleLayers)`.
3. Managers **reconcile** their DOM under `.canvas-elements-container`; they never clear and rebuild it.
   - Glitter fills: an animated GIF `background-image` plus a CSS `mask-image` blob, in a canvas-sized stack the layer transform places (`GlitterManager.syncElementScale`). Anything that reads a pointer against the mask goes through `GlitterManager.getMaskLocalPoint` first; a color pick samples the base image in document px.
   - Text and shapes: a stack of masked spans, one per paint slot, reconciled by `reconcileSlotStack` from `buildSlotStack`. Each manager's `getSlotMask` supplies the mask for a slot. Types declaring `rasterizesScale` redraw vector masks at committed scale, leaving frames and layout logical; paint effects and textures use physical pixels. Preview and export consume the same raster density, while live gestures reuse the previous raster. Smooth distance-field outlines preserve fractional edge coverage when antialiasing is enabled; Sharp uses miter strokes, and Pixel preserves four-neighbor morphology. Scaled text strokes a simplified silhouette contour in output pixels so non-uniform scaling does not stretch outline width. GIF transparency is quantized at final encoding; SceneCompositor retains real alpha.
   - Stickers: an `img`, plus an optional shadow span.
	- Tier-1 filters: recipe operations from `FILTERS` become CSS backdrop and overlay children through their `FILTER_OPS` painters. Tier-3 filters snapshot the layers below through a dedicated `SceneCompositor`, cache that input separately from the processed output, and show the output canvas at the filter's stack position. A snapshot is shown only while its input signature (the serialized layers below) is current: `FilterLayerManager.syncSnapshot` drops a stale one so the live layers show until the re-render lands, and a pressed-pointer gesture on a layer under a displayed snapshot shows the live layers until release (`liveEditing`). `editor.saveState` calls `noteSceneEdited` so edits that skip a preview update are re-checked. `PREFERENCES.filterPreviewLevel` selects Off, Still or Animated; constrained devices fall back from Animated to Still. `GlitterFilter.renderToCanvas` runs the same pixel recipe for preview and export. Displayed cached animated snapshots restart playback in `renderContent`; each snapshot paint clears its canvas before drawing to prevent alpha accumulation.
4. `ViewportManager` zooms and pans by transforming `.preview-wrapper`. Above 100% it applies nearest-neighbor display to the whole stack and commits a compositor repaint after continuous input settles. At 600% and above the optional pixel grid appears. `PixelGridOverlay` draws it on an unscaled canvas beside the wrapper, placing each one-device-pixel line from the viewport transform and `devicePixelRatio`; it hides only during animated view transitions. An animated view change (fit, a sheet or the window opening) is stepped in script on the CSS `ease` curve over `--transition-base`, not left to a CSS transition: the screen-space selection chrome reads the step on screen (`viewTween.shown`) and so moves in the same frame as the canvas. `will-change` is active only during active viewport movement.
5. Layer animation is sampled from `GlitterAnimation.MOTION_REGISTRY` and applied by `AnimationTicker` to a `.layer-anim-wrapper`. Preview and export pass the same sampling context (`area`, `rest`, `restVisual`, `id`, `seed`, `origin`) to the same sampler, and type definitions provide their ticker and timeline hooks.

## Export path

1. `editor.exportCurrentTarget()` resolves the active `EXPORT_TARGETS` entry, snapshots the settings and dispatches through that target's `exporter` key.
2. `SceneCompositor` prepares masks, fonts and sources, then asks each layer manager for its export plan through `LAYER_UI_CONFIG[type].managerKey`. Text, shape and fill-layer managers share the slot-stack compositing path: their `renderSlotMasks(layer)` builds every slot mask with the same functions the preview uses, and `_renderSlotStackToCanvas` composites `buildSlotStack` in order. Every slot, the glitter fill and the canvas background paint through `_paintSourceInto`, and authored sources come from the declared slots (`_getSlotAuthoredSources`). A prepared composition context can be reused by repeated still snapshots without reloading sources or rebuilding masks.
3. `ExportTimeline` and `AuthoredFrameResolver` decide which frames to render and their timing.
4. `SceneCompositor` renders every frame: `planAnimation` plans an animation (GIF pre-renders its kept frames, MP4 gets a schedule and an async renderer for its entries) and `composeFrameAt` composes one still. Filter plans may await pixel operations such as a real JPEG encode/decode round-trip. **All formats use it:** `GifExporter` encodes with `GifEncodingPipeline` and `GifPalette`; `Mp4Exporter` encodes with WebCodecs and the vendored `mp4-muxer`; `StillImageExporter` encodes PNG, JPEG or a still GIF. JPG Quality remains an encoder setting; authored recompression generations belong to the JPEG Crunch filter look, not export settings. The last step of every frame is Export Size: `_renderFrameToCanvas` resamples the composed canvas once (`getExportOutputSize`, `downscaleCanvas`), so every format takes the resized frame from one place and `plan.width`/`plan.height` are output pixels. Scene snapshots (filter previews, the eyedropper) take their settings from `editor.getSceneSnapshotSettings()`, which pins the size to 100%.
5. `ExportResultPresenter` shows the result in Export Ready. `buildExportReport` (`js/export/export-report.js`, DOM-free) turns the blob, target, timeline plan, the encoder's color analysis and the platform into plain data: facts, save guide, primary action, upload limits (`CONFIG.export.sizeTargets`), notices and the Details tables; the presenter only renders it. The Export time table is wall-clock seconds per phase from `createExportPhaseTimer`, which the progress reporters feed. Save uses `saveBlobAs`: a Save As dialog where the browser has `showSaveFilePicker`, otherwise the anchor download. The result's Export as menu and the Export button in Export Settings both re-enter `exportCurrentTarget()`.
6. A size fit runs inside `exportCurrentTarget({ fit })`, or on every export when the Target Size setting names a goal. Exporters hand their finished file to `deliverExportResult`, and the flow takes it through `callbacks.present` so it can compare attempts before Export Ready shows one. `planFitAttempt` (`js/export/export-fit.js`, DOM-free) picks the next step of `CONFIG.export.fit.ladder` from the measured sizes; a target only takes the steps for its `fitLevers`. Overrides apply to the job's settings snapshot and never to the stored export settings. Attempts that change only GIF encoding settings (`GIF_ENCODE_ONLY_SETTINGS`) reuse the composed frames through `frameCache`.

Long export loops give the main thread back with `yieldForExportProgress` (a message task). Never pace export work with `requestAnimationFrame`: it waits for a screen refresh per yield, runs at half rate in iOS Low Power Mode and stops in a hidden tab.

Pixel-level math only: never `ctx.filter`, because iOS Safari doesn't support it. Masks are binarized (`CONFIG.rendering.crispMaskEdges`) so transparent GIF exports don't fringe.

## Undo and redo

- Call `editor.saveState(label)` once per **committed** user edit, not on every slider tick. Slider bindings usually save on commit.
- Repeated small edits share a `coalesceKey`, for example `saveState('Move layer', { coalesceKey: \`nudge:${ids}\` })`.
- A snapshot is `LayerManager.serializeLayer` for every layer, plus canvas size and base-image references. Painted masks are stored separately as versioned binaries; snapshots hold `maskVersion` pointers. Anything that serializes state must account for that.
- Restoring rebuilds the layer objects, so nothing is cached on them. Preview caches live in their manager, keyed by layer id plus a content key (`GlitterManager.maskImages`, `TextGlitterManager.previewMaskUrls`, the `measurementCache` and `maskUrlCache` of `ShapeGlitterManager` and `PathLayerManager`, the `MaskCompositor` caches), so a restored layer reuses them when its content matches.

- A glitter or sticker asset is filed in one style (`category`) and may point at one set (`set`), a creator's collection that spans styles and supplies the credit. Sets are the category-file entries with `kind: 'set'`. Original names, old library-name search terms and imported historical `appearances` remain metadata. Credit resolves item over set over style; Creator browsing derives from the resolved `authorId`. Neither sets nor historical appearances add extra asset records.
- Every Library kind uses `LibraryCatalog` for the category tree, filtered counts and creator membership, `AssetBrowserRail` for the tree picker and Up, and `AssetSetHeader` for descriptions and credit (including brush-pack attribution). Home shows navigation action cards, larger than asset tiles, or all tiles under headings; glitter, stickers and brush tips default to covers, shapes and fonts to all tiles. Creator view has an All creators home. Navigation changes selection without writing category filters. Quick picks reconciles project/recent tiles on the Style home only, retaining their order during picks and resetting priority when home is reopened; Favorites reconciles its tiles in place. Glitter alone uses a 48px tile floor and 2px gaps. Brush Basic tips remain a five-column grid above individual raster pack cards on both Home presentations. All Raster brush sets also shows pack cards; with no active query or filters, only opening a pack expands its brushes. Quick picks, the index lead and navigation covers stay hidden until narrowing is cleared. Grouped walls and narrowed results reuse the set header title/count line. Shape and font managers provide a shared category-preview hook for dropdowns and covers, derived from the first ordered member. Font dropdown glyphs use `js/generated/font-preview-icons.js`, produced from bundled/installed font outlines by `python tools/build-font-preview-icons.py`. BrushTipManager derives a Raster root over the manifest packs; the picker places Basic brushes first after Home, then groups All Raster brush sets and each pack below it. The manager supplies pack categories through getBrowseCategories so these aggregate views keep packs closed when no query or filter is active.

Under a style the picker lists the sets that have tiles in it; a style whose tiles are all one set stands alone and its header carries that set's credit. Creator view lists the styles a creator's tiles are filed in. Search retains score ordering. Original order is a temporary set view option; the last style root is a per-library preference.


## Custom glitter

`js/effects/glitter-recolor.js` reads used GIF colors and rewrites global and local palette entries. It never re-encodes pixels or changes frame timing, disposal or transparent indexes. The phase 1 style allowlist and eight-swatch limit live in `CONFIG.tools.glitter.recolor`. OKLCH adjustments are applied into exact RGB swatches, with chroma reduction for gamut mapping.

Personal collections are named **My Glitter** (recolors and uploaded fill tiles) and **My Stickers** (uploaded stickers), retaining the existing `custom` and `user-uploads` category ids. Covers and dropdown thumbnails include bundled and personal content. Tiles carry an upload or palette origin mark with an accessible label; preset tiles carry neither. A shared upload dialog supports batches of PNG, JPG and GIF, with size/type checks and pixel-rendering classification in `ContentManager`. Uploads live for the session; used assets embed original bytes and filename/MIME metadata in projects. Recolor recipes continue to persist across visits. Static fill images decode to one frame for the compositor, while animated GIF fills use the existing GIF decoder.

`GlitterBrowserManager` registers recolors as ordinary GIF assets with string ids. `PREFERENCES.customGlitter` stores immutable recipes across visits; My Glitter shows them newest first and carries source attribution. Replacement creates a new id and repoints all declared slots, including parked drafts, in one document history step. `ContentManager.deleteUserAsset()` shares confirmation and retirement for uploaded stickers, cutouts, fill tiles and recolors. Deletion clears Favorites/Recents and hides the asset from Quick picks without changing document history. Retired assets remain resolvable for layers, undo, project saving and export but stay out of the Library. Render/export consumers use `getRenderContent()`; browsing uses `getAllContent()`.

Projects embed each referenced recipe and its recolored GIF in `customGlitter`, including assets used by parked slots. They also embed source GIF bytes so exact swatch editing remains possible when the source leaves the manifest. Opening registers the assets before layers deserialize; missing recipes without an embedded GIF or available source follow asset preflight.

## Content modals

`ModalManager` owns an ordered stack and a single inert snapshot. Normal modal registrations replace; `layer: 'dialog'` stacks over the current modal. Browser history stores an array of modal ids; Back dismisses one layer and Forward restores only a base modal, never a resolved dialog. Programmatic Back navigations are chained. Async close guards restore a popped entry before asking so cancellation keeps history aligned with the screen. `editor.chooseAction` owns the shared action dialog, with `confirmAction` as its boolean wrapper. Document modals register through `registerDocumentModal`, which runs shared navigation, references, image scaling and tooltip setup after per-document content initialization.

`modals/*.html` are loaded into the modals at runtime. Every one (guide, welcome, about, preservation, history, personal-web, and any local-only pages) is generated from `content/src/*.src.html` by `node tools/build-modals.js`; edit the source, never the output. How to write a page is in [content/AUTHORING.md](../content/AUTHORING.md).

- **Registries.** `content/entities.json` holds every named site, program, organization, work, person and handle, each with a `kind`; `content/sources.json` holds every citation, shared across pages. `tools/content-registry.js` loads and validates both.
- **Rendering.** `{@slug}` renders by kind: sites get an icon on their first mention per section, glosses become a tooltip on the first mention per page, handles and hosted sites get a hover card (`js/ui/tooltip.js`, reading `js/generated/entities-data.js`). `{references}` renders a page's citations in first-citation order.
- **Generated files.** Each build also writes `css/generated/_entity-icons.scss` (icon variables, handle accents and domain rules, used by `css/modals/_entities.scss`), `js/generated/entities-data.js` (names, kinds and relations for the hover cards and the Preservation timeline filter) and `.vscode/content.code-snippets`. `--check` fails when any of them is stale.
- **Lint.** `tools/modal-lint.js` runs token and structure rules on every page, and the prose rules (em dash, bare dates, bare names) on the articles only.
- The guide's `{ui-tool:…}`, `{ui-tool-icon:…}`, `{ui-panel:…}` and `{ui-shortcuts}` tokens are filled from the app registries at build time, and `tests/unit/shortcut-coverage.js` fails when the built guide is stale. `tests/unit/modal-build-unit.js` fails when any built page is stale or a timeline entity is missing from the registry.
- `docs/local/HISTORY-PAGE-STYLE-GUIDE.md` (local-only) governs the articles' voice and citations.

## Stretchable assets

Sticker assets may carry `slice: {top, right, bottom, left, mode}` in base-image pixels. The admin validates nonnegative integer insets and a nonempty center; modes are `stretch` and `round`. The browse index carries only `sliced`; the full detail and project layer copy carry the insets. Zero insets on one axis describe a three-slice banner.

`js/paint/nine-slice.js` shares source/destination rectangles between reconciled DOM background spans and canvas rendering. Sticker layers copy the metadata and enable Smart Stretch by default; `sliceEnabled` disables it per layer. Protected corners use the smaller scale, or the unsliced axis scale for banners. Pixel-art scale snapping happens in base pixels before variant conversion. Round tiles are bounded by `CONFIG.tools.nineSlice.maxTiles`.

Frame image layers copy slice and variant metadata, default to Smart Stretch when available, and use `frameData.sliceScale` (Border Scale) to size protected borders. Preview, hit alpha, effect masks and exports share sliced geometry. Sticker picking continues to use its existing image-box frame. The library mark/filter, selected asset badge and resize-only guides expose the feature. Source/licensing data for new assets still follows the ordinary sticker authoring workflow.

`ExportProgressPresenter` supplies export labels and cancellation state to `TaskProgressPresenter`. Export and background removal share its card markup, styling, animation, estimates, accessibility announcements and canvas slot ownership. Shared timing lives in `CONFIG.ui.taskProgress`; encoder yielding remains in `CONFIG.export.progress`. `EXPORT_PROGRESS_PHASES` and `reportExportProgress` in `SceneCompositor.js` own labels, counts and format ranges for all encoders; `callbacks.progressFormat` selects GIF, MP4 or still ranges. Phase labels also feed the result timing summary.

## Text layout and editing

`js/core/text-content.js` owns graphemes, source-indexed case conversion, the grapheme limit and measured color-glyph classification. `js/paint/text-layout.js` takes a measuring context and returns lines, runs, source-indexed glyph boxes and decoration rectangles in unshifted text-local space. The text manager uses this layout for masks and warp; editing and Split use its same glyph positions. Whole-line and justified word runs retain font kerning, while letter spacing and warp use grapheme runs. `textData.orientation` is `horizontal` (the default, including older projects) or `stacked`: each displayed grapheme occupies a centered row, and an explicit newline starts a column to the right. Line Height controls row spacing; nonnegative Letter Spacing separates columns. Empty columns retain a font-sized advance. Layout line records carry their actual x and baseline, so masks, background plates, carets, selections, warps and Split share the positions. Fixed boxes hide rows/columns that do not fit and report overflow; Fit box to text uses the full column block.

Text modes are `point`, `autoHeight` and `fixed`; Auto Height stores width alone and holds the transform anchor during reflow. The meme template uses full-width Auto Height boxes anchored at its top and bottom margins. Color emoji adds a generated canvas through the existing image-source stack immediately above Fill. Fill and Bevel use the letters mask; outline, shadow and backgrounds retain the full glyph silhouette. Preview and SceneCompositor read the same text stack and masks.

`js/ui/text-edit.js` and `js/ui/text-actions.js` supply the text manager's editing and action methods. `editSession` is transient UI state. A transparent textarea receives native input, IME and phone keyboard events; the existing text spans remain visible. Both text fields write through `applyTextEdit`; caret and selection overlays read the layout. Committing an edit is one history step, including deletion of empty text. Creation uses `createTextAt` for tool clicks, drags, Add and paste.

Canvas region creation uses `beginCreationGesture`, `updateCreationGesture`, `finishCreationGesture` and `cancelCreationGesture`. The active tool's `onCanvasDrag` receives the box, click classification and starting canvas point; mouse and touch share this path.

## Bounded motion and pending canvas bounds

`MOTION_REGISTRY` declares motion behavior, label, group, targets, fields, active test, anchor storage, bounds requirement and off-canvas export policy. `CONFIG.tools.animation.presets` supplies parameter defaults. `ANIMATION_CONTROLS` owns field bindings and display scales. Panel controllers read these declarations without naming motions or deriving fields from the DOM.

`GlitterAnimation.createSamplingContext` validates `{ area, rest, restVisual, id, seed, origin }`. `getLayerAnimationSamplingContext` supplies document-pixel boxes from `getLayerCanvasBox` and the canonical animation box. Particles supply emitter-space boxes. A bounds-dependent pose returns identity without bounds. Preview and export use `splitSample` to separate canvas-space movement from local transforms. Marquee, fall and rise share `wrapMotion`. Marquee's `repeat` is `none` (leaves the area, then re-enters), `wrap` (a copy enters the opposite edge) or `tile` (a row of copies along the travel line, stepped so neighboring visual boxes meet on their first touching pair of edges plus `gap`, capped by `maxCopies`, crossing whole tiles per cycle; tile steps and offsets are whole pixels so no seam antialiases between copies). Wrapped and tiled samples carry repeated copy offsets, composed through the animation stack; preview reconciles sibling wrappers and export draws the same offsets. Ricochet uses reflection with integer round-trip counts weighted by Angle, so loops close while non-diagonal angles travel different paths on square canvases. Wander uses seeded integer harmonics. The area is read each frame, so resizing adapts motion immediately. Export surfaces use document dimensions; later output scaling does not change motion coordinates.

`TOOLS` declares each tool's key and preferred panel; its commands are generated. A session in `SESSIONS` may name the Inspector `panel` that stands in for the selection's while it lasts, and say that it keeps the Library window shut (`closesLibrary`). `SESSIONS` in `js/core/sessions.js` declares each active predicate, mode, lifecycle handlers and shortcut descriptions. Brush activation, deactivation and mouse/pen presses route through `TOOLS`; text editing ends through its session. Auto Glitter permits commands by their real groups and tool capabilities. Generic session commands dispatch to these declarations; nudge uses `CONFIG.ui.nudge`. `ESCAPE_HANDLERS` tries field blur, modal, picker, drag, edit session and selection in order, stopping after one action and preserving the tool. Temporary Hand resumes the interrupted session without reactivating or ending it.

The Size section owns `documentSize = { operation, scale, bounds, anchor, relative }`. `editor.canvasBounds` reads `bounds`, which is null without pending edits. `CanvasBounds` setters synchronize all views through `syncCanvasBoundsViews`; `CANVAS_BOUNDS_SOURCES` defines Custom, Artwork and Selection fit rectangles and history labels. Fitted rectangles recompute from current layers. Crop is a pointer session over this model, with eight handles, shade, thirds and a size badge supplied by `SelectionChrome`. Moving crop bounds snaps their edges and center using the shared position snapper; dragging outside draws a new rectangle. Pending bounds never enter history. Apply calls `resizeCanvas(width, height, -x, -y)` once. `validateCanvasSize`, `setCanvasSurface` and `refreshAfterCanvasChange` are shared by document sizing and restoration.
