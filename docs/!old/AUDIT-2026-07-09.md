# Glitter Editor - Maintainability and Expansion Audit

**Date:** 2026-07-09  
**Branch:** `masks-and-text`  
**Focus:** maintainability, expansion, consistency, design system

This is the third audit. Prior audit work is done and verified; historical plans live in `docs/!old/`.

---

## Executive summary

The codebase is in good shape for expansion. The main architecture holds:

- `LAYER_UI_CONFIG` is the source of truth for layer-type UI.
- `effect-source.js` protects preview/export parity.
- `CONFIG` owns nearly all user-tunable values.
- `ProjectSerializer` correctly handles versioning plus non-JSON paint-mask state.
- The touch/export/shape verification suites are guarding the right invariants.

Remaining debt is concentrated in two meaningful areas:

1. `app.js` is still very large.
2. The legacy mouse click path still fronts `handleWorkspaceAction`.

The lower-risk cleanup work from this audit is now complete.

---

## Decisions made

1. Keep shared cross-manager logic in plain root scripts with thin delegating class methods; do not introduce inheritance between Text and Shape managers.
2. Tokenize app-layer z-index values, not local component stacking offsets.
3. Keep the Windows-7 theme block self-contained and literal.
4. Do not restructure `app.js` further this round beyond the targeted mouse-path cleanup.

## Conventions

- Panels use purpose-based names: `.layers-panel`, `.preview-panel`, `.design-panel`.
- User-tunable or reused values belong in `js/config.js`; inline fallbacks that restate CONFIG are not allowed.
- Shared JS helpers live in root scripts such as `utils.js`, `color-adjust.js`, `effect-source.js`, and `slot-effects.js`.
- SCSS should prefer semantic tokens when a value repeats or represents an app-layer z-index.
