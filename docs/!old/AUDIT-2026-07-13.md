## 1. Executive Summary

**Overall health: B+.** For a solo, no-build vanilla-JS project, this codebase is in unusually good shape: behavioral regression suites that assert byte-identical export stability, a versioned project-file format with a written migration policy, config discipline that mostly holds, and a self-audit culture whose findings actually get closed. The admin PHP is far better than typical XAMPP-era admin code — prepared statements throughout, CSRF on mutations — and it only ever runs locally.

**Top 3 risks:**
1. `js/app.js` is a 6,655-line, 164-method god class fronting nearly every UI flow — the single biggest drag on every future change.
2. Zero automation — no CI, no lint, no pre-commit — so all conventions (cache-busting, LF, `dbg()`, no inline CONFIG fallbacks) are enforced only by memory; three script tags have already drifted out of the cache-bust convention.
3. The project is not reproducible from the repo — no README, no DB schema for the admin — so a disk failure or second machine means archaeology.

**Top 3 opportunities:** a cheap `node tools/check.js` convention gate; a project save/load round-trip test protecting the newest data-loss surface; and the already-planned app.js decomposition, sequenced *behind* that safety net.

## 2. Repo Map

**Purpose:** browser-based animated glitter GIF/MP4 editor (layers: base image, glitter fill, stickers, text, shapes) with a local PHP admin for curating the glitter/sticker asset library. Personal project (`version: '0.2.0'`, `js/core/config.js:12`), actively developed.

**Stack:** vanilla JS (globals + `<script>` tags, no bundler), SCSS → hand-compiled CSS, PHP/mysqli admin (local only), MySQL (local only), Playwright-driven Node test scripts. Only dev dependencies: `playwright`, `sass`.

Config centralizes in `js/core/config.js` (1,238 lines). Production is the static output (client JS + `data/*.json` snapshots); the admin writes those snapshots locally.

## 3. Audit Report

### Strengths (preserve these)

- **Behavioral test suites of genuinely high quality** — 22 touch checks run twice from fresh launches to catch state leakage; export parity asserts *byte-identity* including edit→undo→re-export (`tests/README.md:73`, `107-118`). These assert behavior, not mere execution. *Fact.*
- **Versioned project format done right** — explicit format rules, validation with human-readable errors, forward-version handling, migration table (`js/classes/ProjectSerializer.js:5-11`, `194-227`). *Fact.*
- **Admin API fundamentals solid** — prepared statements with typed binds throughout `admin/includes/assetAPI.php` (column names come from code-defined lists, not user input); bcrypt + `hash_equals` + `session_regenerate_id` (`auth.php:57-79`); CSRF required on all mutating actions (`api.php:45-62`) and sent by the client (`admin_api.js:33-34`); `.htaccess` restricts to local. *Fact.*
- **Memory-conscious undo** — snapshots share the base-image pixel buffer via a documented replace-only invariant (`js/classes/HistoryManager.js:14-28`). *Fact.*
- **Config discipline mostly holds** — export caps exist (`maxFrames: 60`, hard limit 1000, `config.js:494-532`); the `dbg()` rule genuinely holds (only `console.log` in non-vendor JS is inside `debug.js:3`; the other 46 console calls are `warn`/`error`). *Fact.*
- **XSS-safe user text** — user text reaches the DOM via `textContent`/canvas, not `innerHTML`; TextGlitterManager's innerHTML uses are numeric `formatUnit()` readouts (`TextGlitterManager.js:1357-1564`); layer-name editing uses `input.value`/`textContent` (`LayerManager.js:1338-1356`). *Fact.*
- **Self-audit culture that closes findings** — prior audit items (slot-effects extraction, slider unification, SCSS tokens, panel renames) verifiably done. *Fact.*

## 4. Improvement Strategy

**Theme 1 — Make the conventions self-enforcing** (cache-bust drift, `??` fallbacks, ungated suites).
Target: a single `node tools/check.js` failing on convention violations in <5s without a browser, plus an optional pre-commit hook. Principle: the rules are good and written down; the failure mode is memory, not policy — automate the memory. Trade-off: deliberately **no** ESLint/Prettier/CI services — a bespoke ~150-line checker fits the no-build culture and catches project-specific rules generic tools can't. **Done signal:** `tools/check.js` exits non-zero on: changed JS without a `?v=` bump, script tag missing `?v=`, `console.log` outside debug.js, CRLF in staged text files, and known inline-CONFIG-fallback sites.

**Theme 2 — Protect the data surfaces before the big refactor** (no save/load test, export gate, D6).
Target: project round-trip + the four core suites behind one command, run before any commit touching `js/`. Principle: app.js decomposition is only safe after the behaviors it can break are pinned. Trade-off: no admin tests, no full Playwright CI — Ryan's manual testing covers UX; automation covers what manual testing is bad at (byte-level and serialization regressions). **Done signal:** serialize→load→serialize byte-equality test exists and passes; `node tests/run-core.js` runs it + export-parity + touch-smoke + touch-handle-verify + shape-border-verify.

**Theme 3 — Reproducibility and deployment honesty** (no schema, no README, stale comments).
Target: a fresh machine stands up editor + admin from the repo. Principle: a solo project's biggest operational risk is the bus/disk factor; insurance costs one afternoon. Trade-off: no deploy pipeline — just document what exists (GitHub Pages + local admin). **Done signal:** `admin/schema.sql` recreates the DB; README covers XAMPP setup, DB import, SCSS compile, test commands, and the GitHub Pages deploy reality; `.htaccess` comment tells the truth; example credentials ship an invalid hash.

**Theme 4 — Shrink app.js on the existing rails** (sequenced last, on purpose).
Target: app.js under ~4,000 lines by extracting already-cohesive clusters into `js/core`/`js/ui` with thin delegating methods — the exact pattern D1–D5 proved. Principle: don't invent a new architecture; app.js just predates the one that exists. Trade-off: D6 mouse-path unification stays shelved until Ryan's manual desktop pass; extraction must avoid the click-routing path entirely until then. **Done signal:** settings-persistence, export-settings-UI, and asset-info clusters in their own files; all five suites green; no intended behavior change.

**Explicitly not fixing:** admin N+1 loops (curation scale), gif.js vendoring (stable), ContentManager inheritance (works, low churn), admin innerHTML (single trusted local user — revisit if a second admin appears), admin PHP tests, iOS export memory (no observed failures; measure first), any framework/bundler adoption (fights the project's core identity).
